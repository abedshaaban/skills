# skills

A small library of **agent skills** — self-contained capabilities you drop into
a project so an AI coding agent (Claude Code and compatible harnesses) can pick
them up automatically.

A skill is just a directory with a `SKILL.md` at its root. The front matter
(`name` + `description`) is what the agent reads to decide *when* to use it; the
body and any bundled scripts/assets are loaded only when it actually runs. That
lazy-loading is the whole point: a skill costs almost nothing in context until
it fires.

## Skills in this repo

| Skill | What it does |
|---|---|
| [`un-mcp`](un-mcp/) | **API → Skill converter.** Turns an MCP server, a REST API, API docs, a list of endpoints, or your own wrapper into a lightweight skill backed by direct `curl` scripts — so nothing has to stay loaded in context like a live MCP does. |
| [`trello`](trello/) | **Trello over direct REST.** Read/write boards, lists, cards, comments, checklists, attachments, custom fields, and activity through one `curl` dispatcher instead of the `mcp-server-trello` MCP. |

`trello` was **generated by `un-mcp`** from the Trello MCP — it's the reference
example of what the converter produces.

### Why not just run the MCP?

An MCP server re-injects its tool schemas into the model's context every turn,
whether you use them or not. A skill backed by a `curl` script costs **zero**
context until the moment it runs, and its responses are trimmed by a small
`node` summariser before they ever reach the model. Same operations, far cheaper.

## Install a skill into your project

Each skill lives in its own directory here. To use one, copy it into your
project's skills folder — `.agents/skills/` for most harnesses, `.claude/skills/`
for Claude Code. The `install.sh` helper does this for you:

```bash
# list what's available
./install.sh --list

# copy the trello skill into a project (default target: .agents/skills)
./install.sh trello ~/code/myapp

# Claude Code layout
./install.sh un-mcp ~/code/myapp --dir .claude/skills

# install everything, into the current project
./install.sh all .

# symlink instead of copy, so edits here track into the project
./install.sh trello ~/code/myapp --symlink
```

Or just copy the directory by hand — a skill is only files:

```bash
cp -R trello ~/code/myapp/.agents/skills/
```

After installing, open the skill's `SETUP.md` and fill your project-root `.env`
with the credentials it needs. The scripts auto-source that `.env` (gitignored) —
no manual `export`.

## Add a new skill to this repo

The fastest path is to let `un-mcp` build it: point it at an MCP, an API doc,
an endpoint list, or your own wrapper and ask for a skill. It writes a
`SKILL.md`, a `curl` dispatcher, and a `SETUP.md` following the templates in
[`un-mcp/assets/`](un-mcp/assets/).

To add one by hand, create a top-level directory with at least:

```
<skill-name>/
├── SKILL.md            # required — front matter (name, description) + instructions
├── SETUP.md            # credentials + where to get them (if it needs any)
└── scripts/            # any executable helpers (chmod +x them)
```

`install.sh --list` discovers any top-level directory containing a `SKILL.md`, so
a new skill shows up automatically.

## Layout

```
.
├── README.md
├── install.sh          # copy/symlink a skill into a target project
├── .gitignore          # ignores .env so credentials never get committed
├── un-mcp/             # the API → skill converter
│   ├── SKILL.md
│   ├── assets/         # templates the converter fills in
│   └── references/     # REST-mapping cheatsheet for common services
└── trello/             # example skill produced by un-mcp
    ├── SKILL.md
    ├── SETUP.md
    └── scripts/trello.sh
```
